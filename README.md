# Sold

مشروع بوت Telegram لإدارة استضافة ملفات برامج/بوتات المستخدمين ومتابعة تشغيلها، مع نظام نقاط وواجهات للمستخدم والإدارة. هذا الوصف مستند إلى الملفات الموجودة في المستودع، ولا يعني أن التطبيق أو ميزاته تعمل أو أنها آمنة للإنتاج.

> **الحالة:** لم يكن في المستودع README عند المراجعة. أُعدّت هذه الوثيقة من قراءة ساكنة للملفات فقط؛ لم يُشغّل البرنامج أو البناء أو الاختبارات، ولم تُثبّت اعتماديات.

## الوظائف الظاهرة في المصدر

وفقًا لـ `main.py`، يتضمن المشروع بوت Telegram يعمل بالاستطلاع الطويل، ومسارات لرفع ملفات بامتدادات `.py` و`.js` و`.php` أو أرشيف `.zip`، ثم إرسال طلب للموافقة الإدارية قبل بدء الاستضافة. يظهر في المصدر أيضًا تشغيل البرامج ومتابعتها وإيقافها، وسجلاتها، وتخزين بيانات المستخدمين، وإدارة نقاط ومتجر وطلبات وخطط VIP، وهدايا/إحالات، ونسخ احتياطية وإحصاءات إدارية.

هذه قائمة بما تنفذه الشيفرة أو تحاول تنفيذه، وليست ضمانًا لاكتمال هذه الوظائف. ملفات ZIP، على سبيل المثال، يُبحث فيها عن `main.py`، كما أن بعض خطوات تثبيت اعتماديات البرامج المرفوعة تُنفّذ ديناميكيًا؛ ينبغي التعامل مع كل هذه الملفات والمدخلات على أنها غير موثوقة.

## الملفات الأساسية

| الملف | دوره بحسب محتواه |
|---|---|
| `main.py` | منطق بوت Telegram، رفع الملفات، الإدارة، التخزين، تشغيل البرامج والفوترة. |
| `Dockerfile` | يستخدم صورة Python 3.12، ويثبت أدوات Docker وملف الاعتماديات، ثم يحدد `/start.sh` كنقطة بدء. |
| `requirements (6).txt` | قائمة اعتماديات Python المثبتة الإصدارات؛ اسم الملف غير قياسي، لكنه الاسم الذي يشير إليه `Dockerfile`. |
| `start.sh` | يبدأ `dockerd` في الخلفية، ينتظر مدة ثابتة، ثم يشغّل `main.py`. |
| `fly.toml` | إعداد نشر Fly.io يحدد Dockerfile، إعدادات خدمة/تخزين، ويطلب آلة ذات صلاحية `privileged`. وجود هذا الملف لا يثبت نجاح النشر. |

## المتطلبات والإعداد

المتطلبات التي تدعمها الملفات مباشرة:

- بيئة Python 3.12 كما يحددها `Dockerfile`.
- Docker daemon وواجهة Docker المتاحة للتطبيق؛ يبدأ `start.sh` daemon محليًا، ويطلب إعداد Fly.io صلاحية `privileged`. هذا النمط يمنح صلاحيات عالية ولا ينبغي اعتباره إعدادًا آمنًا أو معزولًا دون مراجعة متخصصة.
- تثبيت الاعتماديات من `requirements (6).txt` كما يفعل `Dockerfile`، إضافةً إلى حزمة Python `docker` التي يثبتها الملف بصورة منفصلة.
- إعداد بوت Telegram. يعرّف المصدر الإعدادين `BOT_TOKEN` و`ADMIN_ID` كثوابت داخل `main.py`؛ لا يظهر في المصدر تحميلهما من متغيرات البيئة. لا تضع أي رمز أو اعتماد سري في المستودع، وانقل الإعدادات إلى تخزين أسرار مناسب قبل أي استخدام.
- يعرّف `fly.toml` اسمي الإعداد `DOCKER_HOST` و`USER_DATA_DIR`. لا تُفترض قيم أخرى أو آلية إعداد محلية غير موثقة في الملفات.

## مسار البدء كما تصفه الملفات

`Dockerfile` يحدد `start.sh` كأمر بدء؛ والسكريبت يشغّل Docker daemon ثم ينفذ `python -u main.py`. هذه ملاحظات عن محتوى الملفات وليست خطوات تشغيل مجرّبة، ولا تؤكد أن daemon سيكون متاحًا أو أن البرنامج سيبدأ بنجاح.

يوجد تعارض/نقص يحتاج التحقق قبل إعداد النشر: يعلن `fly.toml` عن خدمة HTTP على المنفذ 8200، بينما مسار التشغيل الظاهر في `main.py` ينتهي باستطلاع Telegram ولا يظهر فيه خادم HTTP يستمع لذلك المنفذ. لذلك لا توثق هذه الوثيقة أمر نشر أو تعرض المنفذ على أنه خدمة عاملة.

## البيانات والتخزين

ينشئ المصدر مجلدات مثل `uploads/` و`logs/` و`backups/`، وملف قاعدة بيانات JSON محليًا، كما يحفظ ملفات المستخدمين تحت `USER_DATA_DIR`. يحدد إعداد Fly.io وحدة تخزين مستمرة لـ`user_data` فقط؛ لا يثبت ذلك أن قاعدة البيانات والتحميلات والسجلات والنسخ ومفتاح الأمان ستبقى محفوظة بعد إعادة إنشاء الآلة. راجع مسارات التخزين والنسخ والاستعادة قبل الاستخدام، ولا ترفع بيانات المستخدمين أو ملفات الجلسات إلى مستودع عام.

## تنبيهات أمنية وحدود الاستخدام

- **يوجد رمز بوت ثابت في المصدر.** اعتبره مكشوفًا: أبطله/دوّره لدى Telegram قبل أي تشغيل، ثم انقل الرمز إلى مخزن أسرار. لم يُنسخ الرمز إلى هذه الوثيقة.
- يقبل النظام شيفرات وملفات يرفعها المستخدمون ويشغّلها، ويستطيع تثبيت اعتماديات مرفوعة. تشغيل ذلك عبر Docker لا يثبت العزل أو السلامة. كما أن إعداد النشر يطلب تشغيلًا بصلاحية عالية ويتعامل مع Docker daemon/socket؛ أي خطأ في الفصل بين المضيف والحاويات قد يعرّض النظام المضيف وبياناته للخطر.
- يتضمن المصدر محاولة تشفير اختيارية باستخدام `cryptography`؛ عدم توافر المكتبة يجعل بعض المسارات تحفظ البيانات دون تشفير. لا تعتبر التشفير أو فحص السلامة بديلًا عن إدارة المفاتيح والنسخ الآمنة ومراجعة التنفيذ.
- يلزم تحديد حدود الرفع والموارد، وعزل الشبكة والعمليات، وسياسة الاحتفاظ والحذف، وموافقة أصحاب الملفات، ومصدر/سلامة الصور والاعتماديات قبل إتاحة الخدمة. لا تقدم هذه الوثيقة أي ضمان أمني أو تشغيلي.
